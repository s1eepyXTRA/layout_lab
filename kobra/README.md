# Кобра — прототип конструктора дашбордов

Браузерный прототип в стиле Superset: 13 типов графиков, вкладки, текст, нативные фильтры, кросс-фильтрация, синтетические данные продаж DNS, загрузка своих CSV/Excel. Всё хранится в браузере (localStorage, загруженные наборы — IndexedDB), а передаётся между людьми файлом `.kobra.json`.

## Структура

```
src/            исходники: styles.css + JS-модули (порядок сборки: data, engine,
                ui, viz, app, dashboard, explore, datasets, schema, autodash, templates, guided, share, spec)
vendor/         библиотеки: ECharts 5.5.1, marked 12.0.2, DOMPurify 3.1.6, SheetJS 0.18.5, PapaParse 5.4.1
build.py        сборка в один HTML-файл
build/
  index.html    онлайн-версия: библиотеки с CDN
  kobra.html    офлайн-версия: всё внутри файла, открывается двойным щелчком
service/        начатая серверная часть (не закончена)
  backend/app/core.py   настройки, модели метаданных, пароли, сессии, шифрование подключений
  backend/app/demo/     демо-данные DNS в CSV для загрузки в базу
  tools/export_demo.js  выгрузка демо-данных из src/data.js
```

## Макет без данных

Главный путь: «Сделать макет». Набор данных выбирать не нужно — Кобра порождает его сама и прячет за дашбордом. Блоки добавляются видом визуализации («Столбцы», «Линейный график»), а всё содержательное правится прямо на плитке в режиме «Поменять названия и разрезы»: название блока, название показателя, единица измерения (₽, шт., мин), разрез, количество категорий и их названия.

Правка меняет не подпись на экране, а сам скрытый набор, поэтому переименованная категория называется одинаково во всех блоках, а выбранное в фильтрах переезжает на новые названия. Цифры придуманы детерминированно: при перезагрузке они те же, и у того, кому вы передадите макет файлом, — тоже.

Скрытый набор не виден в разделе «Данные», не предлагается при создании графика и удаляется вместе с дашбордом.

## Готовые дашборды

«Дашборды» → «Выбрать готовый дашборд» (или сразу `#/templates`): каталог отчётов, собранных по стандартам визуализации. Шаблон раскладывает дашборд по трём уровням детализации — сводка (что происходит), разбор (за счёт чего), документы (исходные строки) — и описывает нужные поля ролями, а не именами колонок. Кобра подбирает колонки сама, показывает подбор в окне подтверждения и даёт его поправить; недостающие показатели вроде среднего чека дописывает в набор. Уровни включаются галочками, а любой шаблон можно посмотреть на вымышленных данных до того, как появился файл.

Осторожно со словом «шаблон»: в каталоге это готовый дашборд, а в обмене файлами — `.kobra.json` для передачи другому человеку. Это разные вещи.

**Переход по уровням.** Клик по столбцу или сектору фильтрует весь дашборд: выбранное видно на панели фильтров и действует на всех вкладках, а вкладку вы переключаете сами. Своего механизма перехода у Кобры нет намеренно — макет не должен обещать того, чего нет в целевой BI-системе. На первом уровне есть подсказка текстом.

**Простая правка.** В меню дашборда — «Поменять названия и разрезы»: под каждым блоком появляется строка с названием и выбором разреза, а у макета ещё и с показателем, единицей и категориями — без конструктора графика. У дашбордов на своих и встроенных наборах правятся только подписи: данные остаются нетронутыми. Заголовки, которые придумала Кобра, следуют за разрезом; заданные вручную — остаются. Остальные настройки блока не трогаются, для них есть «Больше настроек».

## Наборы-схемы

Набор данных можно не загружать, а описать: «Данные» → «Описать набор», вставить шапку из Excel или перечислить названия колонок. Тип Кобра угадывает по названию, строки придумывает сама — одни и те же при каждом открытии (детерминированный seed в схеме). Нужно, когда дашборд рисуют до того, как появились данные: заказчик накидывает макет для ТЗ, аналитик — макет на согласование. Дашборд с такими наборами честно подписан: «Это макет, данные вымышленные».

## Черновик дашборда одной кнопкой

На странице набора данных есть «Собрать черновик дашборда». Кобра смотрит на колонки набора и сама
собирает отправную точку: плитки с главными числами, динамику по месяцам, столбцы и круговую по
текстовым разрезам, таблицу с показателями, фильтр периода на последние 12 месяцев и один-два
фильтра-списка. Главную метрику выбирает осмысленно — сначала денежную (`₽` или «руб» в подписи,
формат «рубли»), потом любое другое число, и только если считать нечего — количество строк. Названия
графикам даёт человеческие: «Выручка по филиалам», «Выручка по месяцам». Дашборд сразу открывается
в режиме правки: это заготовка, которую правят и дополняют, а не готовый отчёт.

## ТЗ из согласованного макета

У каждого графика есть поля ТЗ (кнопка «ТЗ» в конструкторе графика): бизнес-вопрос, источник данных, периодичность обновления, приоритет и комментарий. На расчёты они не влияют, зато видны в списке графиков и уезжают вместе с графиком в `.kobra.json`.

Меню дашборда → «Выгрузить ТЗ в Markdown» собирает из макета готовое задание: вкладки, по каждому графику — тип визуализации, набор данных, метрики с формулами (`SUM(Выручка, ₽) / COUNT_DISTINCT(Номер заказа)`), разрезы с гранулярностью, фильтры, период и лимиты, из оформления — только то, что меняли руками. Отдельным разделом — нативные фильтры дашборда, в конце — список графиков без бизнес-вопроса. Всё печатается теми же подписями, что видно на экране, поэтому ТЗ не расходится с макетом. Если на дашборде есть набор-схема, в файле стоит пометка, что цифры вымышленные.

## Помощник

В меню дашборда — «Спросить помощника»: панель сбоку, своя переписка у каждого дашборда. Человек описывает задачу или свой процесс словами, помощник предлагает блоки и описание данных; применяется это только по подтверждению и откатывается одним действием вместе с данными и видом блоков.

**Что уходит наружу.** Только названия и типы колонок, формулы показателей и состав дашборда — строк данных нет. Приложить двадцать строк можно отдельной галочкой и только к одному запросу. Кнопка «Что уйдёт» показывает отправляемое целиком до отправки. На макете отправлять нечего: данные там и так придуманы.

**Доступ к модели** задаётся в шестерёнке панели: адрес OpenAI-совместимого эндпоинта, имя модели и токен. Сначала это может быть личный эндпоинт, потом — шлюз компании: меняется настройка, а не код. Токен лежит в этом браузере, поэтому берите персональный, с лимитом и отзываемый.

**Без доступа помощник тоже работает**: «Скопировать запрос» собирает готовый промпт для внешнего чата, «Вставить ответ» разбирает ответ обратно. В офлайн-сборке (`kobra.html` двойным щелчком) это единственный способ: у файла origin `null`, и шлюзы такие запросы режут.

**Придуманные данные** помощник не присылает строками — он описывает колонки, а строки порождает Кобра тем же детерминированным генератором. Готовые строки выгружаются в CSV кнопкой в панели.

## Обмен файлами

«Экспорт в файл» (меню-шестерёнка в шапке, меню дашборда или список дашбордов) складывает дашборды, графики и описания наборов в один `.kobra.json`:

- **Шаблон** — только структура. Строки загруженных файлов не вкладываются; по желанию Кобра подменит их вымышленными, чтобы графики не были пустыми.
- **Проект** — вместе со строками загруженных наборов. Такой файл несёт настоящие данные, с ним аккуратнее.

«Импорт из файла» показывает, что внутри, и при совпадении идентификаторов спрашивает: добавить копией или заменить свои версии.

## Как запустить у себя

Ставить нечего: ни npm, ни зависимостей, ни базы. Нужен только браузер, а для сборки — Python 3
(на Windows команда называется `py`, а не `python3`).

**Самый быстрый способ — ничего не собирать.** В репозитории уже лежит готовая сборка:
откройте `kobra/build/kobra.html` двойным щелчком. Внутри файла все библиотеки, интернет не нужен.

**Собрать из исходников:**

```bash
git clone https://github.com/s1eepyXTRA/layout_lab
cd layout_lab/kobra
python3 build.py           # build/index.html  — библиотеки с CDN, нужен интернет
python3 build.py offline   # build/kobra.html  — всё внутри файла, открывается двойным щелчком
```

**Запустить `index.html` через локальный сервер:**

```bash
python3 -m http.server 8777 --directory build
```

Дальше `http://localhost:8777/index.html`. Онлайн-версии нужен именно `http://`: страницы
переключаются через `history.pushState`, а с `file://` браузер такие переходы запрещает. Офлайн-версия
(`kobra.html`) работает и так, и так.

После правок в `src/` пересоберите обе сборки — в репозитории лежат обе, иначе они разъедутся.
Единственная доступная проверка кода — синтаксис: `for f in src/*.js; do node --check "$f"; done`.

Всё, что вы сделаете, хранится в этом браузере: дашборды и графики — в localStorage
(ключ `kobra.state.v1`), строки загруженных файлов — в IndexedDB. Другой браузер или режим инкогнито
начнут с чистого демо; «Настройки» → «Сбросить всё к начальному состоянию» возвращает исходный вид.

## Ограничения прототипа

- Данные и дашборды живут только в браузере, где открыт файл. Переносятся экспортом в `.kobra.json`.
- Выгрузки самих данных нет: ни картинок, ни Excel, ни PDF — есть «Посмотреть данные» и экспорт дашбордов.
- Относительные периоды («последние 12 месяцев») считаются от последней даты в данных: для демо DNS это 31.08.2026, для набора-схемы — конец его периода.
- У наборов-схем период фиксируется при создании, иначе цифры менялись бы каждый день.
