# Proposal

## Why

Про то, как работать с Коброй, написано только в `README.md` репозитория — то есть для того, кто
открывает исходники. Человек, которому дали ссылку на сервис, не читает README: он видит пустой
экран «С чего начнём» и четыре карточки, а дальше догадывается сам. Половина возможностей — простая
правка подписями, макет на придуманных данных, выгрузка ТЗ для аналитика, обмен файлами, сборка по
описанию — не видна, пока не наткнёшься.

Подсказками внутри экранов это не лечится: правило интерфейса — одна короткая строка, и объяснять
там «зачем вообще макет» нельзя, иначе экран превращается в учебник. Значит нужна отдельная
страница, куда это объяснение и уезжает.

## What Changes

- В шестерёнке появляется пункт «Документация», он открывает отдельную страницу.
- Страница — список разделов, каждый разворачивается и сворачивается: открыт тот, который нужен, а
  не весь текст сразу.
- Разделы отвечают на вопросы, с которыми человек приходит: с чего начать, чем шаблон отличается от
  дашборда, откуда берутся цифры в макете, как поправить не ломая, как отдать работу аналитику, кто
  что видит, как собрать по описанию словами.
- Состояние «что развёрнуто» не запоминается между заходами: человек приходит с новым вопросом, а не
  с прошлым.
- Доступна всегда: и за сервисом, и в офлайн-сборке, и до того, как человек собрал первый шаблон.

## Capabilities

### New Capabilities
- `user-docs`: встроенная документация для того, кто пользуется Коброй, а не правит её код.

## Impact

- Клиент: новый файл `src/docs.js` (страница и её содержимое), маршрут `#/docs`, пункт в шестерёнке,
  стили раскрывающихся разделов.
- Текст документации — в коде, как и всё остальное в этом прототипе: отдельного хранилища для него
  нет и не нужно, он едет вместе со сборкой и работает в офлайн-варианте.
- `README.md` проекта остаётся для разработчика: часть, объясняющая работу с интерфейсом, теперь
  есть и внутри продукта, и расходиться им нельзя — в README остаётся ссылка на страницу.
