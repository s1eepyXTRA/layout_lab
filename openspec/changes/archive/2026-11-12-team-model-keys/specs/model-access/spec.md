# Spec Delta

## MODIFIED Requirements

### Requirement: Доступ к модели настраивает сервис, а не человек

Адрес шлюза, таймаут и ключ по умолчанию SHALL задаваться настройками сервиса. Ключ MUST NOT
попадать в браузер ни в ответе, ни в настройках интерфейса. Человек SHALL узнавать только, доступна
ему модель или нет.

#### Scenario: Человек работает за сервисом

- **WHEN** человек собирает шаблон по описанию в сервисе
- **THEN** он нигде не вводит ни адрес шлюза, ни ключ — обращение идёт настройками сервиса

#### Scenario: Модель не настроена

- **WHEN** сервис развёрнут без настроенного доступа к модели
- **THEN** интерфейс говорит, что модель недоступна, и предлагает перенос вручную

#### Scenario: Человек смотрит, что отдаёт сервис

- **WHEN** интерфейс спрашивает сервис о его состоянии до входа
- **THEN** в ответе сказано лишь, есть ли в сервисе доступ к модели, без адреса шлюза, названия
  модели и без ответа на вопрос «можно ли мне»

#### Scenario: Человек узнаёт, можно ли ему

- **WHEN** человек вошёл в сервис
- **THEN** вместе со сведениями о себе он получает признак, доступна ли модель его команде

## ADDED Requirements

### Requirement: Ключ к модели выдаётся на команду

Сервис SHALL хранить ключ к модели отдельно для каждой команды. Обращение к модели SHALL идти ключом
команды человека. Команде без своего ключа SHALL использоваться ключ по умолчанию из настроек
сервиса, а при его отсутствии обращение SHALL быть отклонено с объяснением, что доступ команде не
выдан. У команды SHALL быть возможность задать свой алиас модели.

#### Scenario: У команды есть свой ключ

- **WHEN** человек из команды, которой выдан ключ, собирает шаблон по описанию
- **THEN** обращение идёт ключом его команды, и расход ложится на бюджет этого ключа

#### Scenario: У команды ключа нет, но есть ключ по умолчанию

- **WHEN** человек из команды без своего ключа собирает шаблон по описанию
- **THEN** обращение идёт ключом по умолчанию — развёртывание на одну команду работает как раньше

#### Scenario: Ключа нет ни у команды, ни по умолчанию

- **WHEN** человек из команды без ключа собирает шаблон, а ключа по умолчанию в сервисе нет
- **THEN** ему сказано, что администратор не выдал его команде доступ к модели, и предложен перенос
  вручную

#### Scenario: У команды свой алиас модели

- **WHEN** ключу команды в шлюзе разрешена другая модель, и администратор назвал её алиас
- **THEN** обращения этой команды идут к этой модели, остальных — к модели по умолчанию

### Requirement: Ключи команд администрирует только администратор

Экран управления ключами SHALL быть доступен только роли администратора. Ключ SHALL задаваться и
отзываться в интерфейсе, без изменения развёртывания. Введённый ключ MUST NOT возвращаться наружу
ни в каком ответе сервиса, включая ответ администратору, который его задал.

#### Scenario: Администратор выдаёт команде доступ

- **WHEN** администратор вставляет ключ, предназначенный команде
- **THEN** ключ сохраняется для этой команды, и люди команды могут собирать шаблоны по описанию

#### Scenario: Администратор смотрит, кому выдан доступ

- **WHEN** администратор открывает экран ключей
- **THEN** он видит команды, у каких из них ключ задан, кем и когда — но не сами ключи

#### Scenario: Ключ отзывают

- **WHEN** администратор отзывает ключ команды
- **THEN** обращения этой команды к модели прекращаются, а перенос вручную остаётся доступным

#### Scenario: Ключи просит не администратор

- **WHEN** экран или список ключей запрашивает человек без роли администратора
- **THEN** сервис отказывает

#### Scenario: Ключ не читается

- **WHEN** ключ команды не удаётся расшифровать (сменился ключ шифрования сервиса)
- **THEN** человеку сказано, что ключ его команды не читается и нужно сказать администратору, а
  обращения к модели не происходит

### Requirement: Расход команды отделён от расхода остальных

Журнал обращений SHALL хранить команду, от имени которой шло обращение, и то, чьим ключом оно шло —
своим или ключом по умолчанию. Расход одной команды MUST NOT быть неотличим от расхода другой.

#### Scenario: Разбор расхода по командам

- **WHEN** администратор смотрит, сколько потрачено за период
- **THEN** расход виден по командам, а не только по людям

#### Scenario: Команда работает на ключе по умолчанию

- **WHEN** у команды нет своего ключа и обращения идут ключом по умолчанию
- **THEN** это видно и в журнале, и на экране ключей: иначе отсутствие своего ключа незаметно

#### Scenario: Человек перешёл в другую команду

- **WHEN** человек сменил команду после обращений к модели
- **THEN** прежние обращения остаются за той командой, чьим ключом они шли
