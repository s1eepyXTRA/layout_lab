# Design

## Context

Зачем — `proposal.md`. Что должно получиться — `specs/server-storage/spec.md`.

Как сейчас:

- `MAX_UPLOAD_ROWS` объявлена (`app/core.py:28`, умолчание 50 000) и не встречается больше нигде в
  сервисе.
- Действует только предел размера файла: `MAX_FILE_MB = 512` (`app/upload.py:29`), отказ 413.
- Таблица набора создаётся в рантайме (`app/ingest.py:284`), строки заливаются `COPY`
  (`app/ingest.py:208`), индексов нет.
- В клиенте предел свой — `MAX_UPLOAD_ROWS = 300000` (`src/datasets.js:6`), и предупреждение о срезке
  показывается **только** в локальном режиме (`src/datasets.js:311`).

## Goals / Non-Goals

**Goals:**

- Предел строк действительно ограничивает.
- Человек знает предел до загрузки и видит факт срезки после.
- Период на большом наборе не читает таблицу целиком.

**Non-Goals:**

- Партиционирование таблиц наборов и колоночное хранение. Предел строк делает это ненужным на
  обозримом объёме.
- Индексы по всем колонкам. Разрезы меняются, время — нет: у каждого набора есть `mainDttm`, и
  фильтр по периоду стоит почти на каждом дашборде.
- Автоматический `VACUUM`/`ANALYZE` по расписанию. После `COPY` достаточно одного `ANALYZE` в той же
  задаче.
- Докачка файла частями и возобновление. Это другая задача.

## Decisions

### Останавливаться на пределе, а не отказывать

Разбор доходит до предела и завершается успешно, пометив набор числом загруженных строк и фактом
срезки. Альтернатива — отказать целиком (413 по числу строк) — выглядит честнее, но на практике
означает «ваш файл не подходит, идите режьте его сами», тогда как первые 50 000 строк для макета
шаблона обычно и нужны. В браузерной версии ведём себя так же много лет (`data.slice(0, MAX)`), и
человеку это понятно.

Факт срезки виден там же, где число строк набора: на его странице. Молчать нельзя — иначе человек
построит шаблон по части данных и не узнает об этом.

### Предел называется до загрузки

Клиент узнаёт пределы от сервиса (в описании режима) и показывает их на экране выбора файла — оба,
и размер, и число строк. Сегодня в серверном режиме предупреждение не показывается вовсе, потому
что клиентский предел к серверу отношения не имеет; значит, пределы должен называть тот, кто их
применяет.

### Индекс по времени после `COPY`, в той же задаче

`CREATE INDEX` на колонку `mainDttm` сразу после заливки, затем `ANALYZE`. Строить индекс **после**
`COPY`, а не до: на заливке он только замедляет вставку и получается хуже по плотности.

Индекс — обычный btree по одной колонке. Составные (время плюс разрез) не делаем: разрезы у каждого
дашборда свои, а угадывать их на загрузке значит угадывать неверно.

Для наборов, залитых до изменения, индекс создаётся одноразовым шагом — не миграцией Alembic, потому
что таблицы наборов намеренно спрятаны от автогенерации (`alembic/env.py`, `include_object`), и
миграция о них знать не должна. Шаг идёт командой роли `migrate` отдельным флагом.

## Risks / Trade-offs

- **Человек не заметит срезку и построит шаблон по части данных** → число строк и предел на странице
  набора, плюс пометка в списке данных.
- **Индекс на наборе из 50 000 строк не нужен и только занимает место** → он мал (единицы мегабайт),
  а планировщик сам решает, использовать его или нет.
- **Одноразовый шаг для старых наборов забудут запустить** → без него всё работает как раньше, просто
  медленнее; шаг идемпотентен (`CREATE INDEX IF NOT EXISTS`).
- **Предел строк и предел размера файла могут противоречить друг другу** → называем оба, и первым
  срабатывает тот, который достигнут раньше; размер проверяется до разбора, строки — во время.

## Migration Plan

1. Выезжает новый образ: предел действует для новых загрузок, индекс создаётся для новых наборов.
2. Одноразовый шаг для существующих наборов (`migrate --index-datasets`): `CREATE INDEX IF NOT
   EXISTS` по колонке времени каждого набора плюс `ANALYZE`. Запускается на работающем сервисе;
   `CREATE INDEX` без `CONCURRENTLY` блокирует запись в таблицу набора, а не чтение — для набора,
   который не грузится в этот момент, это незаметно.
3. Откат: вернуть образ. Индексы можно оставить — они не мешают старому коду.
