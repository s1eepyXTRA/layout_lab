# Proposal

## Why

Всё, что человек собрал в Кобре, лежит в его браузере: `localStorage` и IndexedDB. Из этого следуют
три вещи, которые нельзя починить в интерфейсе. Шаблон, собранный аналитиком, не виден заказчику —
«поделиться» ничего не значит, пока объект лежит на одной машине, и единственный способ передать
работу остаётся файлом `.kobra.json`. Права (`canView`/`canEdit`/`canShare`) проверяются только в
интерфейсе, то есть не проверяются: состояние правится инструментами разработчика. Вход по LDAP
нарисован, потому что bind из браузера невозможен в принципе.

Прототип своё отработал: путь «собрал макет — согласовал — выгрузил ТЗ» понятен, и дальше его нужно
отдавать команде. Для этого у Кобры должен появиться сервер.

## What Changes

- Появляется **API** (FastAPI) поверх уже написанного `kobra/service/backend/app/core.py`: настройки
  из `KOBRA_*`, модели метаданных, bcrypt, JWT и шифрование строк подключения там уже есть.
- **Postgres** становится местом, где живут шаблоны, графики, наборы, пользователи и настройки, а
  также строки загруженных CSV/Excel (схема `kobra_uploads`). Наборы-схемы хранятся описанием и
  `seed` — строки по-прежнему порождает клиент, их незачем возить по сети.
- **Миграции** (Alembic) прокатываются до старта приложения.
- **Вход переезжает на сервер**: пароль в базе или bind в LDAP, сессия — JWT. Конфигурация остаётся
  именами FAB (`AUTH_TYPE`, `AUTH_LDAP_SERVER`, `AUTH_ROLES_MAPPING`), как сейчас в `auth.js`.
- **Права проверяются на сервере** теми же правилами, по тем же полям `owner_login`/`team`/`shared`.
  Клиентские `canView`/`canEdit`/`canShare` остаются — но как подсказка интерфейсу, а не как защита.
- **Redis** берёт на себя кэш выдачи, очередь Celery для тяжёлых операций (разбор большого файла,
  экспорт), ограничение частоты запросов и список отозванных сессий.
- **Упаковка**: один образ (собранный `build/index.html` плюс API), `docker compose` для разработки,
  Helm-чарт с `Deployment`/`Service`/`Ingress`, секретами и job-ом миграций.
- **BREAKING**: у клиента появляются два режима хранения. Серверный — основной: состояние едет в
  API. Локальный — то, что есть сейчас; он остаётся для офлайн-сборки `kobra.html`, которую
  открывают двойным щелчком без всякого сервера. Общего состояния между режимами нет, перенос —
  через `.kobra.json`.

Что **не** меняется: расчёт остаётся в браузере (`runQuery` по массиву в памяти), генератор строк
по схеме остаётся на клиенте, обмен файлами `.kobra.json` остаётся, снимки и откат (`store.js`)
остаются локальными.

## Capabilities

### New Capabilities

- `server-storage`: шаблоны, графики и наборы живут на сервере и видны всем, кому положено; клиент
  синхронизируется с ним и внятно ведёт себя, когда сети нет; строки загруженных файлов хранятся в
  базе, а их разбор идёт фоновой задачей с видимым состоянием.
- `server-auth`: вход проверяется сервером (база или LDAP), сессия выдаётся и отзывается сервером,
  и каждый запрос к данным проходит проверку прав по тем же правилам, что показывает интерфейс.
- `deployment`: сервис разворачивается одним образом с внешними Postgres и Redis, настраивается
  переменными `KOBRA_*`, прокатывает миграции до старта и не требует ручных действий при обновлении.

### Modified Capabilities

Нет. Поведение экранов — каталог шаблонов, макет без данных, простая правка, сборка по описанию —
не меняется: меняется то, где лежит результат.

## Impact

- `kobra/src/app.js` — `saveState()`/`saveSoon()`/`boot()`/`loadUploaded()`: единственная точка, через
  которую состояние уходит в хранилище, становится сетевой и асинхронной.
- `kobra/src/datasets.js` — строки загруженных наборов уезжают из IndexedDB в базу.
- `kobra/src/auth.js` — экран входа, справочник сотрудников и настройки доступа работают через API;
  правила прав остаются на месте.
- `kobra/service/backend/` — вырастает из одного `core.py` в приложение: роутеры, схемы, миграции,
  фоновые задачи.
- Новые зависимости бэкенда: FastAPI, uvicorn, Alembic, Celery, redis-py, драйвер Postgres,
  LDAP-клиент. У клиента зависимостей по-прежнему нет.
- `kobra/build.py` не меняется: его результат просто кладётся в образ.
- Граница прототипа, записанная в `CLAUDE.md` («сервера нет, состояние в localStorage, права — это
  ограничение интерфейса»), после этого изменения перестаёт быть верной и должна быть переписана.
