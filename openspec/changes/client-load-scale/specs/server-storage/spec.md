# Spec Delta

## ADDED Requirements

### Requirement: Список объектов приходит без тел

Список объектов SHALL содержать только то, что нужно карточке: имя, владельца, команду, доступ,
версию, время и автора последней правки и краткую сводку содержимого. Тела объектов MUST NOT
отправляться списком. Тело SHALL приезжать при открытии объекта.

#### Scenario: Человек открыл раздел шаблонов

- **WHEN** человек открывает список шаблонов
- **THEN** карточки показаны полностью — с миниатюрой раскладки и пометкой макета — а параметры
  блоков по сети не приезжали

#### Scenario: Человек открыл шаблон

- **WHEN** человек открывает шаблон из списка
- **THEN** его тело запрашивается в этот момент, и дашборд рисуется как раньше

#### Scenario: Список длиннее страницы

- **WHEN** объектов больше, чем помещается на страницу
- **THEN** список отдаётся частями, и клиент не обязан держать их все сразу

### Requirement: Время запуска не зависит от числа чужих объектов

Запуск приложения SHALL занимать время, не растущее с числом объектов в сервисе. Запросы к спискам
SHALL идти параллельно. Человеку с правом видеть всё MUST NOT требоваться загрузка всей работы
компании, чтобы открыть своё.

#### Scenario: В сервисе тысячи объектов

- **WHEN** человек с ролью, видящей чужую работу, открывает Кобру в сервисе с тысячами шаблонов и
  графиков
- **THEN** приложение открывается за то же время, что и в сервисе с десятком объектов

#### Scenario: Один список недоступен

- **WHEN** один из запросов к спискам не удался
- **THEN** человек видит, что именно не загрузилось, а не пустое приложение

### Requirement: Одновременных расчётов не больше заданного числа

Клиент SHALL ограничивать число одновременных запросов на расчёт. Остальные SHALL ждать очереди, а
порядок появления блоков MUST сохраняться. Открытие одного дашборда MUST NOT занимать весь пул
соединений сервиса.

#### Scenario: Дашборд из двадцати блоков

- **WHEN** человек открывает дашборд с двумя десятками блоков
- **THEN** расчёты идут порциями, блоки заполняются по мере готовности, и сервис остаётся отзывчивым
  для других людей

#### Scenario: Человек ушёл со страницы

- **WHEN** человек уходит с дашборда, пока часть расчётов ещё в очереди
- **THEN** ожидающие расчёты отменяются и сервис их не считает
